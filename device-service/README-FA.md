# سرویس ویندوزی مدیریت دستگاه‌های تردد — راهنمای کامل

این سرویس، پل ارتباطی میان **دستگاه‌های تردد** (ZKTeco، Suprema، Anviz، Virdi و...) و **سامانه جامع منابع انسانی** است و به‌صورت سرویس ویندوز اجرا می‌شود.

## قابلیت‌ها

| قابلیت | توضیح |
|---------|-------|
| **پل ADMS/PUSH** | سرور HTTP داخلی روی پورت ۸۰۸۱ — دستگاه‌های ZKTeco با پروتکل استاندارد PUSH (`/iclock/cdata?SN=...`) به آن متصل می‌شوند |
| **خواندن رکوردهای تردد** | رکوردهای ATTLOG دستگاه به‌صورت خودکار تجزیه و به سامانه مرکزی ارسال می‌شود |
| **انتقال کاربر بین دستگاه‌ها** | از UI سامانه (مانیتور دستگاه‌ها → انتقال کاربر) دستور push/delete به هر تعداد دستگاه صف می‌شود و این سرویس اجرا می‌کند |
| **بازکردن درب از راه دور** | `CONTROL DEVICE` از مسیر ADMS یا CMD_UNLOCK از مسیر TCP |
| **همگام‌سازی ساعت دستگاه** | دستور SET OPTIONS DateTime یا CMD_SET_TIME |
| **ری‌استارت دستگاه** | RESTART |
| **پاک‌سازی داده‌ها** | CLEAR DATA |
| **حذف کاربر از دستگاه** | DATA DELETE USERINFO یا CMD_DELETE_USER |
| **تشخیص آفلاین** | ثبت آخرین اتصال هر دستگاه؛ سامانه دستگاه‌های بدون اتصال را آفلاین و هشدار می‌سازد |
| **اجرای مستقیم TCP** | برای دستگاه‌های بدون ADMS با آداپتور پروتکل ZK (پورت ۴۳۷۰) |

## نصب روی ویندوز سرور

```bat
:: پیش‌نیاز: Node.js 18+ (https://nodejs.org)
cd device-service
npm install

:: ۱) کانفیگ را ویرایش کنید (نام کاربری/رمز سرویس + آدرس سرور + فهرست دستگاه‌ها)
notepad config.json

:: ۲) تست حالت کنسول (لاگ زنده می‌بیند)
npm run console

:: ۳) نصب به‌عنوان سرویس ویندوز
npm run install-service

:: حذف سرویس
npm run uninstall-service
```

## تنظیم کانفیگ (`config.json`)

```json
{
  "apiBase": "http://SERVER_IP:3000",
  "username": "svc_bridge",
  "password": "Bridge@1234",
  "listenPort": 8081,
  "devices": [
    { "serial": "ZK-U2000-0142", "transport": "tcp",  "ip": "192.168.10.11", "port": 4370, "commKey": 0, "pollIntervalSec": 60 },
    { "serial": "ZK-FD7-0311",   "transport": "adms", "pollIntervalSec": 60 }
  ]
}
```

- `transport: "adms"` — دستگاه باید در تنظیمات شبکه خودش، آدرس **ADMS/Push** را روی `http://SERVER_IP:8081` تنظیم کند (منو: Comm → Cloud Server / ADMS).
- `transport: "tcp"` — سرویس مستقیم به IP دستگاه و پورت ۴۳۷۰ متصل می‌شود (`commKey` = کلید ارتباط دستگاه).
- `svc_bridge` حساب سرویس است که در سامانه seed شده و فقط مجوز عملیات دستگاه/تردد دارد.

## مسیر داده (جریان معماری)

```
دستگاه تردد ──push (ADMS)──► سرویس ویندوزی (پورت ۸۰۸۱)
        ◄──دستور صف‌شده──              │ HTTP + Bearer
                                      ▼
                        سامانه جامع (Next.js — پورت ۳۰۰۰)
                        POST /api/devices/webhook  (records/ack/status)
                        GET  /api/devices/webhook?SN=  (دستورات صف)
```

## اجرای دستورات از UI سامانه

بخش **مانیتور دستگاه‌ها** در سامانه:
- دکمه‌های «بازکردن درب»، «تنظیم ساعت»، «به‌روزرسانی»، «ری‌استارت»
- «انتقال کاربر» — انتخاب پرسنل + دستگاه‌های مقصد (یا همه)
- «چرخش توکن» — تعویض توکن امنیتی webhook دستگاه
- «گزارش دستورات» — وضعیت هر دستور: در انتظار / تحویل‌شده / اجراشده / ناموفق

## عیب‌یابی

| مشکل | راه‌حل |
|------|--------|
| دستگاه وصل نمی‌شود | فایروال پورت ۸۰۸۱ باز باشد؛ آدرس ADMS دستگاه درست باشد؛ `ping` از سرور به دستگاه |
| `ورود سرویس ناموفق` | نام کاربری/رمز `svc_bridge` در سامانه را بررسی کنید (کاربران → فعال بودن حساب) |
| دستور اجرا نمی‌شود | گزارش دستورات در UI را ببینید؛ دستگاه باید آنلاین باشد تا صف تحویل شود |
| فریمور غیرمتعارف | قالب دستورات در `lib/adms.mjs` (commandToAdms) را متناسب با مستندات دستگاه تنظیم کنید |
| لاگ‌ها | فایل `device-bridge.log` در پوشه سرویس |
