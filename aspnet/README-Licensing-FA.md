# 🔒 مجوز نصب و قفل ضدکپی (فاز ۴۶ + استودیو صدور فاز ۴۷ + «فقط با مجوز» فاز ۸۳ب)

سامانه به سخت‌افزار سرورِ نصب **قفل نرم‌افزاری** خورده است: هر نصب فقط با فایل مجوزِ
امضاشده‌ای که «اثر انگشت همان سرور» در آن گنجانده شده باشد، فعال می‌شود.
**فاز ۸۳ب — فقط با مجوز:** راه‌اندازی اولیه و اجرای سامانه بدون مجوز معتبر ممکن نیست؛
حالت Off و دورهٔ آزمایشی خودکارِ بدون مجوز حذف شده‌اند.

---

## ۱. اصول کار

| جزء | توضیح |
|---|---|
| اثر انگشت سخت‌افزار | از `MachineGuid` ویندوز (ریجستری) یا `/etc/machine-id` لینوکس + نام ماشین ساخته می‌شود؛ قالب `XXXXX-XXXXX-XXXXX-XXXXX-XXXXX` |
| فایل مجوز (`.dat`) | `base64(JSON بدنه) + "." + base64(امضای RSA-2048/SHA256)` — کوچک‌ترین دستکاری → امضا رد می‌شود |
| کلید خصوصی | فقط نزد شما (تولیدکننده) در `private.pem` — **هرگز با نصب مشتری منتشر نشود** |
| کلید عمومی | داخل برنامه جاسازی شده (`Services/LicenseService.cs → PublicKeySpki`) |
| اجرای آزمایشی | فقط با مجوز — مجوزی که تاریخ انقضا دارد (صادره از LicenseStudio/LicenseGen)؛ دورهٔ آزمایشی خودکارِ بدون مجوز وجود ندارد (فاز ۸۳ب) |
| سقف پرسنل | در مجوز درج می‌شود و هنگام ثبت پرسنل جدید کنترل می‌گردد |

**حالت اجرا (فاز ۸۳ب):** همیشه «فقط با مجوز» است — `License:Mode` دیگر خوانده نمی‌شود.
بدون مجوز معتبر (Missing / منقضی / ماشین دیگر / فایل جعلی) ناوبری کامل صفحه به
`/License/Notice` می‌رود و بنر قرمز بالای صفحه‌ها دیده می‌شود؛ فقط `/License`، `/Auth`،
`/health` و `/Setup` (و `/api` و پل دستگاه‌ها برای سلامت داده‌ها) باز می‌مانند.
اگر صادرکننده در مجوز `LockMode: lock` بگذارد، قفل سخت اعمال می‌شود (فاز ۷۸).

## ۲. گردش کار فعال‌سازی مشتری (فاز ۵۰ — با فایل درخواست، بدون تایپ دستی)

1. مشتری نرم‌افزار را نصب می‌کند؛ ویزارد راه‌اندازی اولیه فقط با فایل مجوز کامل می‌شود —
   ابتدا از ویزارد جفت‌کلید بسازید (private.pem را دانلود و نگه دارید)، مجوز را با
   LicenseStudio صادر و همان‌جا وارد کنید؛ بدون مجوز، هیچ تنظیمی ذخیره نمی‌شود (فاز ۸۳ب).
2. از منوی «مدیریت سیستم ← مجوز نصب» (`/License`) دکمهٔ **«دانلود فایل درخواست (.hrreq)»** را می‌زند
   (یا اثر انگشت را کپی می‌کند) و فایل را برای شما می‌فرستد.
   فایل `.hrreq` یک JSON کوچک است: `machine` (امضای سرور) + `company` + `version` + `createdAt`.
3. شما مجوز صادر می‌کنید — با فایل درخواست، امضا و نام شرکت خودکار خوانده می‌شود:

```bash
cd tools/LicenseGen
dotnet run -- issue \
  --key /path/to/private.pem \
  --req pars-hrreq.hrreq \
  --expires 2027-10-25 \
  --max-employees 500 \
  --notes "قرارداد شماره ۱۲۳" \
  --out pars-license.dat
```

   (روش قدیمی هم سر جای خودش است: `--licensee "شرکت مشتری" --machine XXXXX-…`)

4. فایل `.dat` را برای مشتری بفرستید؛ او در `/License` آن را بارگذاری می‌کند — سامانه بلافاصله باز می‌شود.

> **برنامهٔ مجزای گرافیکی (فاز ۴۷):** به‌جای خط فرمان می‌توانید از **استودیو مجوز نصب**
> (`tools/LicenseStudio` — WinForms فارسی/راست‌به‌چپ؛ ابزار عمومی و بدون پیشوند HR) استفاده کنید؛ بستهٔ آمادهٔ اجرا
> (اکزی خودکفا + private.pem + راهنما) در `download/LicenseStudio.zip` قرار دارد.
> کارها: صدور مجوز با تاریخ شمسی، بررسی/بازخوانی مجوز، تاریخچهٔ صدور همهٔ سرورها،
> کپی کلید عمومی برای چرخش کلید — بدون نیاز به نصب .NET روی ویندوز.

## ۳. ابزارهای صدور (فقط سمت شما)

### الف) استودیو مجوز نصب — GUI ویندوزی (توصیه‌شده)

- مسیر سورس: `tools/LicenseStudio` — بستهٔ آماده: `download/LicenseStudio.zip`
- کلید خصوصی داخل برنامه **جاسازی نمی‌شود**؛ برنامه `private.pem` را کنار فایل اجرایی
  (یا پوشهٔ کاربر) می‌یابد و مسیرش را به‌خاطر می‌سپارد.
- **فاز ۵۰:** فونت وزیر (Vazirmatn) جاسازی‌شده؛ «بازکردن فایل درخواست مشتری (.hrreq)»
  امضا و نام شرکت را خودکار پر می‌کند؛ «چسباندن امضا» برای متن کپی‌شده؛
  «مدت اعتبار» و «سقف پرسنل» گزینه‌های آمادهٔ قابل انتخاب دارند (تاریخ شمسی خودکار پر می‌شود).
- تب‌ها: «صدور مجوز» (امضا + دارنده + مدت اعتبار + سقف پرسنل + یادداشت)،
  «بررسی مجوز» (بازبینی هر فایل مجوز + تطبیق امضا)، «تاریخچهٔ صدور» (تمام مجوزهای
  صادرشده با کپی متن)، «راهنما».
- موتور صدور/بررسی با خط فرمان و سرور round-trip تست شده است
  (`scripts/LicenseCoreTest` — ۱۸ چک سبز).

### ب) ابزار خط فرمان LicenseGen — برای سرورهای بدون رابط گرافیکی و خودکارسازی

**آیا با وجود استودیو هنوز لازم است؟ بله — حذف نشود.** هر دو ابزار از یک موتور مشترک
(`LicenseCore.cs`) استفاده می‌کنند و خروجی‌شان بیت‌به‌بیت یکسان است؛ تفاوت فقط در نحوهٔ استفاده است:

| ابزار | کاربرد مناسب |
|-------|--------------|
| **استودیو مجوز نصب** (GUI) | کار روزمره روی ویندوز — همه‌کاره: ساخت جفت‌کلید (فاز ۵۱)، صدور، بازبینی، تاریخچه |
| **LicenseGen** (CLI) | سرور لینوکسی بدون GUI، اتصال SSH، اسکریپت/خودکارسازی، اجرای دسته‌ای |

```bash
dotnet run --project tools/LicenseGen -- keygen  ./keys            # ساخت جفت‌کلید (یک‌بار)
dotnet run --project tools/LicenseGen -- issue   --key ./keys/private.pem --req pars.hrreq --expires 2027-03-20 --out pars.dat
dotnet run --project tools/LicenseGen -- show    license.dat --pub ./keys/public.pem   # بازبینی مجوز
```

### ج) خوداتکا از صفحهٔ «مجوز نصب» (فاز ۵۳ — بدون نیاز به هیچ ابزاری)

در صفحهٔ **/License → بخش «کلید امضای مجوز»** (فقط مدیر ارشد):

1. **«ساخت جفت‌کلید جدید»** — جفت‌کلید RSA-2048 سمت سرور ساخته می‌شود؛ کلید عمومی همان
   لحظه مبنای پذیرش امضا می‌شود و اثر انگشتش روی صفحه دیده می‌شود.
2. **«دانلود کلید خصوصی (private.pem)»** — فایل PEM واقعی (PKCS#8) دانلود می‌شود؛ همان فایلی
   که در LicenseStudio («انتخاب فایل کلید») یا LicenseGen (`--key`) برای امضا استفاده می‌شود.
3. **«حذف جفت‌کلید»** — مجوزهای امضاشده با آن کلید همان لحظه نامعتبر می‌شوند (کش وضعیت فوری
   باطل می‌شود).

نکته‌های امنیتی: کلید خصوصی روی دیسک فقط **رمزشده** (Data Protection، مسیر
`App_Data/license-keys/private.pem`) نگه داشته می‌شود و تنها راه بیرون‌کشیدنش همین دانلود است.
مجوزهای امضاشده با کلید مرجع جاسازی‌شدهٔ تولیدکننده **همیشه** هم معتبرند (هر دو مسیر پذیرفته
می‌شود). هرکس private.pem را دارد می‌تواند برای این نصب مجوز بسازد — آن را در جای امن نگه دارید.

## ۴. تنظیمات (`appsettings.json` — و فایل رمزشدهٔ نصب)

```json
"License": {
  "Mode": "Strict",                // فاز ۸۳ب: همیشه فقط با مجوز (مقدار دیگر خوانده نمی‌شود)
  "File": "App_Data/license.dat"
}
```

(فاز ۸۳ب — حالت Off و `TrialDays` حذف شدند؛ فاز ۵۱ — انقضا سامانه را از کار نمی‌اندازد؛
فقط پس از هر ورود صفحهٔ هشدار «/License/Notice» نمایش داده می‌شود و با تایید کاربر ادامه پیدا می‌کند؛
با `LockMode: lock` در خود مجوز، قفل سخت اعمال می‌شود.)

## ۵. نکات امنیتی

- ⚠️ `private.pem` و کلیدهای `tools/keys/` هرگز وارد بستهٔ نصب، ریپوی مشتری یا بکاپ اشتراکی نشوند (در `.gitignore` هستند).
- اگر کلید خصوصی لو رفت: در استودیو با «🔑 ساخت جفت‌کلید جدید…» (یا `LicenseGen keygen`) جفت‌کلید جدید بسازید، کلید عمومی جدید را در `LicenseService.PublicKeySpki` و `EmbeddedKeys.cs` جایگزین و نسخهٔ جدید منتشر کنید؛ مجوزهای قبلی باطل می‌شوند.
- مسیر فایل مجوز را می‌توانید با `License:File` به بیرون از پوشهٔ برنامه ببرید (مثلاً درایو جدا) تا با کپی پوشهٔ برنامه جابه‌جا نشود.

## ۶. پاسخ صادقانه به «چطور حتی با هوش مصنوعی هم دور زده نشود؟»

هیچ نرم‌افزاری که **روی سرور مشتری** اجرا شود را نمی‌توان ۱۰۰٪ نفوذناپذیر کرد — این قانون
فیزیک مهندسی معکوس است، نه ضعف این سامانه. آنچه این پیاده‌سازی انجام می‌دهد، بالا بردن
«هزینهٔ دورزدن» تا بالاتر از «قیمت مجوز» است:

| لایه | چه چیزی را می‌بندد |
|---|---|
| امضای RSA + اثر انگشت سخت‌افزار | کپی ساده روی سرور دیگر، دستکاری تاریخ/دارنده |
| «فقط با مجوز» (فاز ۸۳ب) | اجرا بدون مجوز ممکن نیست — دورهٔ آزمایشی خودکار و حالت Off وجود ندارد که دور زده شود |
| سقف پرسنل در مجوز | استفادهٔ فراتر از ظرفیت خریداری‌شده |
| انتشار بدون سورس (publish) + حذف فایل‌های `*.cs` | دیدن منطق توسط ابزارهای خودکار |
| Obfuscation تجاری (مثل .NET Reactor با Necrobit / ConfuserEx) | دیکامپایل تمیز با ILSpy — IL به کد بومی تبدیل و کنترل‌فلو مخدوش می‌شود؛ ابزارهای هوش مصنوعی بدون مواد خامِ IL عملاً کاری از پیش نمی‌برند |
| `dotnet publish -p:PublishReadyToRun=true` | ترکیبی از کد بومی + IL؛ دیکامپایل را سخت‌تر می‌کند |
| فعال‌سازی آنلاین (سرور لایسنس شما) | قوی‌ترین لایهٔ عملی: مجوز کوتاه‌مدت که هر چند روز باید با سرور شما تمدید شود |
| ماژول سخت‌افزاری USB (Dongle) | تقریباً غیرقابل دورزدن بدون سخت‌افزار فیزیکی |
| راهکار نهایی: میزبانی سرویس نزد شما (SaaS) | مشتری فقط کلاینت دارد — تنها روش تقریباً ۱۰۰٪ |

پیشنهاد اجرایی برای شروع: همین قفل فعلی + انتشار Release بدون سورس + Obfuscator تجاری.
اگر مشتری‌های حساس‌تری داشتید، لایهٔ «تمدید آنلاین» را اضافه کنید.

## ۷. LicenseStudio ۱.۵.۳ — حالت اجرای قفل + بررسی با کلید دلخواه (فاز ۷۸)

**«حالت اجرای قفل» حالا در خود فایل مجوز درج می‌شود** — صادرکنندهٔ مجوز در تب «صدور مجوز»
استودیو (و در LicenseGen با `--lock-mode warn|lock`) آن را مشخص می‌کند و این انتخاب روی سرور
مشتری از `License:Mode` تنظیمات **اولویت** دارد:

| مقدار | رفتار سرور مشتری هنگام انقضا/نامعتبرشدن مجوز |
|---|---|
| پیش‌فرض سرور (غایب) | طبق `License:Mode` مشتری — `Strict` = فقط هشدار (فاز ۵۱)، `Off` = فقط نمایش وضعیت |
| `warn` | فقط صفحهٔ هشدار + بنر؛ سامانه باز می‌ماند، تایید کاربر کافی است |
| `lock` | **قفل سخت** — صفحه‌های سامانه تا ورود مجوز معتبر به `/License/Notice` می‌روند، AJAX پاسخ 403 می‌گیرد و دکمهٔ تایید اثر ندارد؛ `/api` و پل دستگاه‌ها برای سلامت داده‌ها باز می‌مانند |

- سازگاری کامل به عقب: مجوزهای قدیمی بدون `lockMode` = پیش‌فرض سرور (بدون هیچ تغییر رفتار).
- صفحهٔ `/License` حالت مؤثر را («طبق مجوز» یا «طبق تنظیمات سرور») نشان می‌دهد.
- **رفع باگ «امضای دیجیتال تایید نشد» در تب بررسی:** مجوزهایی که با جفت‌کلید دیگری
  (مثلاً کلید ساخته‌شده در صفحهٔ مجوز سرور مشتری) امضا شده‌اند، حالا با دکمهٔ
  «انتخاب کلید عمومی (public.pem / SPKI)…» قابل بررسی‌اند — با نمایش اثر انگشت کلید فعال
  و دکمهٔ «بازگشت به کلید سازنده». (سرور از قبل هر دو کلید را می‌پذیرفت؛ استودیو فقط کلید
  سازنده را — این عدم‌تقارن رفع شد.)
- راست‌چین‌سازی کامل‌تر فرم‌ها: همهٔ MessageBox ها راست‌چین و راست‌تراز (RtlReading + RightAlign).
- هارنس تست: `scripts/LicenseCoreTest` — ۲۳ چک سبز (شامل ۶ چک جدید حالت قفل).
